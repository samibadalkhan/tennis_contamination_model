### Correction (2026-09-21): tiebreak-orientation bug in the forecaster

`forecast.p_set` added P(B wins the tiebreak) instead of its complement when B
served the first tiebreak point, biasing every `p_match` forecast **toward 0.5**
(set-win probability is provably first-server-invariant; the fixed code now
passes that regression test). Consequences, all re-run:

- **Gate 1 (2014): 0.6044 → 0.6100** (gap +0.018, still passes within 0.02). The
  earlier number was better partly because the bug accidentally regularized a
  **mildly overconfident** model — which is why a principled toward-0.5 forecast
  rule (the tuned burst simulator) is now the motivated next step.
- 2019 checkpoint: 0.6424 → 0.6530.
- `robust_check` re-run on the corrected forecaster; conclusions unchanged.

Trials logged append-only in `results/trials.jsonl` (~630 and climbing); nothing
has been reset.

## Findings so far — the match-only arm

Two separable results on the 2014 development season (tuned on 2013, iid and
point-by-point simulated forecasts; `results/sim_forecast/`):

**A. The simulated burst forecast is a real, standalone win.** Replacing the iid
analytic forecast with a point-by-point simulation that injects a tuned
contamination rate drops log loss **0.6100 → 0.5984** for the ordinary arm —
essentially Ingram's 0.592. This is the ablation's top row: within-match
dependence plus calibrated toward-0.5 shrinkage improves calibration
independent of estimation. (It is also the principled version of what the
tiebreak bug was doing by accident.)

**B. Robust estimation does not beat ordinary — a resolved negative.** With each
arm given its own tuned simulated forecast:

| arm | tuned rate | log loss | paired gain vs ordinary (tourney-clustered) |
|---|---|---|---|
| ordinary | 0.35 | 0.5984 | — |
| robust (cap 2.5) | 0.35 | 0.5993 | −0.0009 [−0.0045, +0.0028] — a tie |
| robust (cap 1.345) | 0.20 | 0.6041 | −0.0057 [−0.0113, −0.0002] — worse |

At its best (loose cap) robust ties ordinary; the tight cap is significantly
worse. The design's own diagnostic agrees: robust should tune a HIGHER
contamination rate than ordinary if it had removed real contamination — instead
it tunes the same (cap 2.5) or lower (cap 1.345), i.e. it removed nothing worth
removing and the tight cap over-blurred genuine skill. The CI half-width (~0.004)
is well below any interesting effect, so this is a genuine **negative**, not
inconclusive: at match granularity the gain is calibration, not estimation.

The one place robust could still matter is the **hybrid/slam-point arm**, where
point bursts are visible; but the synthetic gate showed point-scale bursts are
near-invisible through per-match serve counts, and this confirms it at the
estimator level.

Synthetic gate (`results/synthetic/`): robust recovers planted contamination
decisively at tournament/match scale, costs little when clean, lags boundedly on
permanent jumps — the machinery works, which is what makes the real-data null
interpretable rather than a broken-method artifact.

## Data pipeline

- **Fetched & hash-verified**: slam point-by-point (2011–2024, uneven slam
  coverage by year), ATP + WTA match files (2000–2026), Match Charting Project.
  Per-file SHA-256 against `data/MANIFEST.json`; `--verify` is a hard stop.
  ATP/WTA provenance is weaker than slam's (snapshot, no recorded upstream SHA)
  — the hashes carry the trust burden there.
- **Derived processed layer** (`data/processed/*.parquet`, built by
  `src/build_processed.py`): adds `canonical_name` (accent-stripped,
  first-initial + surname) to fix cross-year name fragmentation (e.g. "D. Thiem"
  vs "Dominic Thiem"), without ever touching the raw CSVs. 1,942 canonical
  identities from 2,770 raw name strings; 9 curated true collisions (e.g. "A.
  Beck" = two different players) flagged `ambiguous_identity` rather than
  merged or dropped.
- **Split**: develop ≤2024, test = 2025 ATP season (2,944 matches, single-use).
  Slam points end Oct 2024, so all point data lives in development and feeds
  the hybrid arm only.

## The model (ordinary arm, reproduced)

```
P(server wins a point) = sigmoid(α_surface + s_i − r_j)
```

`s_i`, `r_j` are each player's serve/return skill — Gaussian beliefs that
random-walk over time (variance `σ²` per year). Fit online (Kalman/Laplace
filtering; no PPL is installed in this environment, so this hand-rolled filter
*is* the inference). Serve-win probabilities feed an exact point→game→set→match
recursion (`src/forecast.py`) for the match forecast.

**Chosen on 2013, scored on 2014 (Gate 1):** `σ = 0.03`/yr, `prior_var = 1.0`.

![Hyperparameter tuning grids](results/plots/tuning_grids.png)

Both tuning years pick a small drift and are fairly flat near the optimum —
match-scale ability moves slowly. 2018 preferred a larger `σ = 0.05`; still
small in absolute terms.

## Season results

![Season log loss and accuracy](results/plots/season_scores.png)

2014 lands within 0.012 of Ingram's reported log loss — the baseline is
validated. 2019 is worse on both metrics, but so is the naive ATP-rank
favorite that season (67.5% accuracy in 2014 vs. 61.3% in 2019, recomputed
directly from `p1_rank`/`p2_rank`) — **the model still beats the rank baseline
in both years** (67.9% vs. 67.5% in 2014; 64.3% vs. 61.3% in 2019). 2019 was a
genuinely harder season to forecast (more upsets), not a broken model.

## Surface effect

![Serve dominance by surface](results/plots/alpha_by_surface.png)

Baseline serve-win probability (average server vs. average returner, pooled
pre-2025): clay lowest (61.2%), grass highest (65.5%) — matches known tennis
physics and is why the spec requires surface-specific intercepts rather than
one pooled α.

## Skill trajectories

![Skill trajectories, 2000-2019](results/plots/skill_trajectories.png)

The filter recovers real career arcs despite a slow drift rate: Djokovic's
serve skill starts weak (~2004–05, still developing) and climbs to rival
Federer/Karlović by the mid-2010s; Karlović's return skill — always the
weakest of the four — drifts further down as he ages past 35. Skills separate
cleanly by role: the same four players rank very differently on serve vs.
return (Karlović is #1 on serve, near-last on return; Djokovic is the reverse).

## Notable findings this session

- **Anti-momentum artifact (resolved):** an earlier momentum diagnostic looked
  like winning points *reduces* future win probability. Simulating i.i.d.
  points under actual scoring rules reproduced ~95% of that signal as a
  deuce-alternation artifact of the permutation null, not a real effect —
  the diagnostic was measuring the null's own structure.
- **Raw data is immutable by design:** when asked to "relabel the datasets,"
  the fix was a derived `data/processed/` layer with `canonical_name`, not
  editing the raw CSVs — preserves SHA verification and the CC BY-NC-SA chain
  of custody.
- **Power check correction:** the Stage 0 power check initially used the CI on
  absolute cross-entropy (±0.022) as the detectable-effect floor. Since both
  arms score the *same* matches, the right floor is the CI on the **paired
  per-match difference** (±0.0155, conservative) — the naive version would have
  read as underpowered when it isn't.
